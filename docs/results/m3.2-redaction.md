# M3.2: redaction leaks and false positives

2026-10-09 · local kind cluster · Vector 0.58.0 · [ADR 0003](../adr/0003-redaction-on-by-default.md)

Two questions: does any injected PII reach the hot sink, and what does redaction mask that isn't PII?

## Leaks: 0 of 5,054 fixtures

The fixture injector (`make fixtures RATE=4`) wrote 4 fixtures/s to the Wikimedia topic and 4/s to its pod's stdout. Each carried one fictional SSN, email, phone number or member ID twice: in free text and in a nested field. `make leak-check` then counted, over a window, the tagged fixtures that reached Loki, and searched every stream Spillway writes for any fixture value.

| Phase | Setup | Window | Fixtures delivered | Values found | Result |
|---|---|---|---:|---:|---|
| A | No LogPipelines: fixtures take the platform paths (`redact_feed`, `redact_pods`) | 3 m | 260 | 0 | PASS |
| B | `edits` (Kafka, [example](../../examples/edits.yaml)) and `support` (claims the `fixtures` namespace), both with redaction left at its default | 10 m | 4,794 of 4,800 injected | 0 | PASS |
| C | `support` with `redaction: {disabled: true}` | 1 m | 474 | 234, all from `support` | **FAIL**, as it must |

Phase B per stream:

| Stream | Fixtures delivered | Delivered without a mask | Fixture values found |
|---|---:|---:|---|
| `team=edits` | 2,398 | 0 | 0 |
| `team=support` | 2,396 | 0 | 0 |

Phase C shows the check can fail. With one team's redaction turned off, every one of that team's fixtures is caught. The other team stays clean, and `make leak-check` exits non-zero:

| Stream | Fixtures delivered | Delivered without a mask | Fixture values found |
|---|---:|---:|---|
| `team=edits` | 240 | 0 | 0 |
| `team=support` | 234 | 234 | ssn 59, email 58, phone 58, memberId 59 |

```

FAIL: 234 fixture values and 234 unmasked fixtures in the hot sink.
```

The 6 fixtures missing in phase B were in flight at the edges of the window; `edits`' 25/s budget didn't drop any at 4 fixtures/s plus Wikimedia's traffic.

## False positives: 3 of 20,004 live events (0.015%)

`make redaction-fp` captured 10 minutes of the live Wikimedia recentchange stream (20,004 events, 385,704 string fields, 17.6 MB of text, 16:21–16:31 UTC). It ran each pattern alone over every event through the real vector binary, and diffed every string. Wikimedia's public edit stream isn't a place for personal data, so every match is a candidate false positive, checked by hand below.

| Pattern | Events changed (M3.2) | Events changed (M3.1 `\b` patterns) |
|---|---:|---:|
| ssn | 2 (0.010%) | 0 |
| email | 1 (0.005%) | 1 |
| phone | 0 | 0 |
| memberId | 0 | 0 |
| **any** | **3 (0.015%)** | **1 (0.005%)** |

Every match:

| Pattern | Matched | Where | Verdict |
|---|---|---|---|
| ssn | `178-03-0000` | Commons file name: `…--010178-03--010178-03-00008…PDF` (title, title_url, meta.uri) | False positive: an archive reference made of digit-dash runs |
| ssn | `721-12-2012` | `meta.uri` and `title_url` of `File:كاف هوي فطيح سوسه21-12-2012.jpg` | False positive: a date. In the URL, the Arabic letter before it is percent-encoded (`%D9%87`), and the hex `87` completes the SSN shape. The plain title doesn't match |
| email | `au_poste@video.davduf.net`, `user@server.domain` | A Wikidata edit setting property P12622 (a PeerTube channel address) | Arguably not a false positive: a public fediverse handle has an address's shape and identifies a person. The M3.1 pattern masks it too |

So dropping word boundaries cost two extra masked events in 20,004, both digit runs inside file names. Against that, the corpus shows the `\b` patterns leaking SSNs and member IDs in escaped JSON, after labels, and after `\t` and ` ` escapes (18 cases on those two patterns alone).

## Limits

- **One feeder:** Wikimedia's text is mostly titles, wiki markup and Wikidata claims. Pod logs and the GitHub events feeder (M3.7) will have more numbers and IDs, so the false-positive rate needs re-measuring there.
- **Known misses** are listed in [`corpus.yaml`](../../internal/redact/testdata/corpus.yaml) (`notMasked`): SSNs and phone numbers without separators, phone numbers outside North America, hand-obfuscated addresses (`jo [at] example [dot] com`). The test fails if one of them starts being masked, so the list stays accurate.
- **The fixture ranges are narrow:** the leak check proves that what was injected didn't leak. The corpus, not the live run, covers the other shapes a value can take.

## Reproduce

```
make up && make fixtures RATE=4
kubectl apply -f examples/edits.yaml -f <a spec claiming the fixtures namespace>
make leak-check WINDOW=10m       # after both pipelines are Ready
make redaction-fp DURATION=600   # needs no cluster
```
